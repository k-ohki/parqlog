# 性能・容量の計測結果（合成データ）

計測日: 2026-11-25。環境: Linux コンテナ（2 vCPU、メモリ 7GB）、開発ビルド（DuckDB は -O2）。
Windows 実機・リリースビルドではこれ以上の速度が見込めますが、確定値は実機で取り直してください。

## データ

`tsd-gen backfill` で 100 系列（装置10台 × 10項目、1Hz）を生成。

| 層 | 期間 | 備考 |
| --- | --- | --- |
| 生データ 32bit | 直近14日 | 日次 Parquet（V2 エンコーディング、ZSTD レベル9） |
| 生データ 16bit | その前の7日 | `*.q16.parquet` |
| 1分集計 | 400日 | 月次 Parquet と DuckDB |
| 1時間集計 | 5年 | DuckDB |

値は温度（0.1 刻み）・圧力（0.01 刻み）・運転状態（0/1）・電流（ノイズあり）の4種類。実データより規則的です。

## 容量

| 対象 | 1日あたり | 1点あたり | 5年の見込み |
| --- | --- | --- | --- |
| 生データ 32bit | 8.4 MB | 1.02 バイト | 1年分 3.0 GB |
| 生データ 16bit | 5.9 MB | 0.72 バイト | 4年分 8.5 GB |
| 1分集計 | 0.86 MB | — | 約 1.6 GB |
| 1時間集計（DuckDB） | — | — | 約 0.2 GB |

合計で約 13 GB（5年、100系列）。仕様書の見積もり（30〜130 GB）より小さいのは、
Parquet V2 の DELTA_BINARY_PACKED で時刻列がほぼ 0 バイトになるためです（V1 では時刻列だけで 1.3 バイト/点）。
ノイズの大きい実データでは値の列が大きくなります。

## 取り込み（`tsd-gen bench`、4並列、1リクエスト 5,000 行）

| 条件 | 受け付け速度 |
| --- | --- |
| 1,000 系列（新規登録を含む）、非圧縮 | 54 万点/秒 |
| 同上、gzip | 120 万点/秒 |

定常の 100 点/秒、目標の 10 万点/秒を十分に上回ります。

## 再現手順

```sh
cargo build --workspace --all-targets
target/debug/tsd-gen backfill --data-dir ./bench/data --raw-days 21 --compact-after-days 14 --m1-days 400 --h1-days 1826
target/debug/tsd run --config ./bench/tsd.toml      # storage.data_dir = ./bench/data
target/debug/tsd-gen bench --points 2000000
```
